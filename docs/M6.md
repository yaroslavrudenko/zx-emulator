# M6 — snapshots and tape

Design for `crates/spectrum`. `MACHINE.md`'s milestone table says **`.z80`/`.sna` snapshots, `.tap`
tape — gate: a real game runs.**

Each decision below carries the class of evidence behind the claim that forced it, using the four
names the README already defines — **proven**, **measured**, **derived**, **observed** — plus
**ruling** for a choice that no evidence forces and that is recorded so it is not re-litigated. A
ruling is not evidence, and where one is doing load-bearing work this document says what would
replace it.

> **Every byte-level format detail below is a pointer, not a specification.** Offsets, page
> numbers, flag-bit positions and the T-state encoding are named here because the *design* turns on
> them — on which fields exist, which are irregular, and which are unrepresentable — and they are
> written from familiarity with the formats rather than from the formats. The implementer
> transcribes each one from the format description, which is the same act the hand-transcribed
> vectors of Decision 7 require anyway. A number in this document that disagrees with the format
> description is a defect in this document.

## The two things that make M6 different from M5

**M6 has an oracle, and M5 did not.** Not for the machine — for the *files*. `MACHINE.md` opens
with *"there is no oracle here"*, and for contention and timing that is still exactly true. But a
snapshot format is an interoperation contract with dozens of independent implementations: a `.z80`
we write either loads in somebody else's emulator or it does not, and a `.z80` they wrote either
loads here or it does not. That is a real external check on our *reading of the format*, and it is
the one place in the machine layer where an independent implementation exists to be checked
against. M6 should use it deliberately rather than stumble into it.

**M6's stated gate grades the wrong thing, if the tape is built the obvious way.** "A real game
runs" is `MACHINE.md`'s verification item 5 — *known-demanding software*, explicitly labelled
observation. Built one way it is observation of the machine. Built the other way it is observation
of a shortcut that bypasses the machine entirely. Decision 4 is that fork, and it is the largest
decision in this document.

## Decision 1 — modules in `crates/spectrum`, not a new crate — **ruling**, with one measurable consequence

`ARCHITECTURE.md`'s crate table already answers half of this in its own text:

```
crates/spectrum/    the machine: paged memory, ULA, contention, keyboard, tape, AY.
```

The tape is named as part of this crate, and the reason holds: a tape is a peripheral that reads
the frame clock and drives a bus line. It cannot be anywhere else without exporting the clock.

The snapshot half is the real question, because a parser genuinely needs no machine. The argument
that settles it is not taste and not layering — it is the **public API delta**, which is the cost
this project treats as permanent.

A snapshot applier needs to do three things the machine does not currently expose:

| It must | Today |
|---|---|
| set the border without performing an `OUT` | only `Ula::out_port`, which charges an I/O machine cycle |
| set the frame position | `Clock::advance` is `pub(crate)`, and `Ula::clock()` returns a `Copy` **by value** |
| write RAM banks | `Memory::write` — sufficient at M6, see below |

A separate crate would have to reach those through `spectrum`'s **public** surface, so all three
become public items, permanently, for one in-workspace caller. As modules inside `spectrum` they
are `pub(crate)` and the public surface grows by **zero** items on `Ula`, `Memory` and `Clock`.
That is the whole argument, and it is checkable rather than aesthetic.

The purity that a crate boundary is usually bought for is achieved by the *signature* instead, and
this workspace already has the pattern: `crates/testsupport` splits `absence_verdict` (a pure
function of its inputs) from `skip_absent_corpus` (the shell that reads the environment), and its
own documentation says why — *"every rule has a failing case that costs microseconds on every
`cargo test`"*. M6 takes the same shape:

- **Pure:** `parse(&[u8]) -> Result<Snapshot, Error>` and `write(&Snapshot) -> Vec<u8>`. No
  filesystem, no machine, no clock. Exhaustively testable, fuzzable, and unchanged under WASM at
  M8 because they never touch `std::fs`.
- **Shell:** `Spectrum::restore` / `Spectrum::snapshot`, which are the only code that touches a
  machine.

Nothing here reads a file. `Spectrum::new(&rom)` already takes bytes rather than a path, and every
new entry point matches it.

**Layout:**

```
crates/spectrum/src/snapshot/mod.rs   Snapshot, Error, Spectrum::restore / ::snapshot
crates/spectrum/src/snapshot/reader.rs  the cursor every parser consumes through (Decision 6)
crates/spectrum/src/snapshot/z80.rs   .z80 v1/v2/v3 read, v3 write
crates/spectrum/src/snapshot/sna.rs   .sna read
crates/spectrum/src/tape/mod.rs       Tape: the pulse train and its playback
crates/spectrum/src/tape/tap.rs       .tap -> pulse train
```

**Rejected: a `crates/snapshot` crate.** It inverts the cost calculus above, and the boundary it
would draw has no analogue to the one that justifies `z80` / `spectrum` — *"the CPU does not own
memory"* is a statement about ownership on the hot path. A snapshot is not a layer of the machine;
it is the machine's own state written down.

**Rejected: a cargo feature.** A feature flag is a second build configuration that nothing tests,
and `cargo test` would only ever exercise one of them.

## Decision 2 — the canonical representation is the machine's state, not a file format — **ruling**

`.z80` v3 is the richest format, and making it the internal representation is tempting for exactly
that reason. It is wrong: every quirk then leaks inward — the "byte 12 = 255 means version 1"
compatibility hack, the `PC = 0` sentinel that marks v2+, the hardware-mode byte, the three-way
split of the T-state counter. The machine would end up storing a file.

So there is one native type, and the two formats are two lossy encodings of it:

```rust
/// Everything a snapshot restores, in the machine's own terms.
pub struct Snapshot {
    /// The CPU, exactly as `Cpu::state()` reports it.
    pub cpu: CpuState,
    /// The colour last written to the border.
    pub border: Colour,
    /// T-states into the frame. Values at or above `T_STATES_PER_FRAME` roll over when
    /// applied, as the clock does everywhere else.
    pub frame_t_state: u32,
    banks: [Option<Box<[u8; PAGE_SIZE]>>; BANK_COUNT],
}
```

Three design points, each with a reason:

**The memory image is keyed by bank, not by address.** This is `ARCHITECTURE.md` Decision 5
applied where it happens to also be the *cheaper* choice today, not only the future-proof one.
`.z80` v2/v3 stores pages by number, and the 48K's three page numbers are **neither contiguous nor
derivable from the 128's rule**: a 128 file numbers page *N* as RAM bank *N − 3*, and a 48K file
uses pages 4, 5 and 8 for `0x8000`, `0xC000` and `0x4000` — which in this crate's bank numbering
are banks 2, 0 and 5. Only the last of those satisfies *N − 3*. So the mapping is a three-entry
table with an exception in it, and an address-keyed `Snapshot` forces that table to exist twice —
once in the parser and once in the writer — with nothing tying them together and a known-irregular
rule to get wrong in both. Bank-keyed, it is one table in one place. That is an SSOT argument in
the present tense; that M7 needs it anyway is a bonus, not the reason.

**That irregularity is also the reason the table is transcribed rather than computed.** It is
exactly the shape that invites a formula — `page = bank + 3` is right for the 128 and right for one
of the 48K's three entries — and a formula that is right two thirds of the time passes any test
built from itself.

**Public fields where there is no invariant, following `CpuState`'s own precedent** — *"Every
combination of these values is a state a real Z80 can be in, so the fields are public and carry no
invariants to protect."* The same test passes here for three of the four: `CpuState` is already
such a type, `Colour::new` wraps into range, and an out-of-range `frame_t_state` is absorbed by
`Clock::advance`'s documented rollover. The banks are private because *which* bank indices are
meaningful is a property of the model, and the parser is where that is decided (Decision 6).

**`Debug` is written, not derived** — `Memory` already had to solve this, for the same reason:
*"a derived `Debug` prints 160 KB of page contents, which makes every failing assertion involving
a machine unreadable."* `Snapshot`'s `Debug` prints the CPU state, the border, the frame position,
and a per-bank checksum, so an `assert_eq!` failure names *which bank* diverged instead of
emitting 96 KB of hex. The gate then reports the first differing address itself.

### What `restore` does, and what it must not do

`restore` sets state. It steps nothing, ticks nothing, and charges no contention:

1. `cpu.set_state(snapshot.cpu)` — which already clears `ei_pending`, and already documents why
   (*"it belongs to an instruction that is no longer running"*).
2. `ula.set_border(snapshot.border)` — **not** `out_port`. Routing a restore through the bus would
   charge a four-T-state I/O cycle that never happened and, worse, would leave `Ula`'s
   `covered_t_states` armed at 4, so the first four ticks of the *next* instruction would be
   charged as an open cycle and skip their contention. That is a concrete defect, not a
   preference, and it is why this setter is unavoidable.
3. `ula.set_frame_t_state(snapshot.frame_t_state)` — the frame **counter** is left alone.
   `frames()` is the machine's uptime since power-on: the boot gate asserts on it and the FLASH
   phase derives from it, and rewinding it on a load would make one number mean two things. **This
   is a convention** — no format carries a frame count — and its cost is stated under *What
   nothing covers*.
4. RAM, bank by bank, through `Memory::write` at the addresses the **slot map** puts each bank at.

Point 4 is the one to look at twice, because it decides whether `Memory` grows public API.

**It does not, at M6.** The three banks a 48K snapshot carries — 5, 2 and 0 — are exactly the three
the 48K slot map exposes, at `0x4000`, `0x8000` and `0xC000`. Reaching them through `Memory::slots()`
(which is already public) rather than through hard-coded addresses means the code is derived from
the slot map rather than from the 48K's particular one. `Memory::bank` / `bank_mut` become
**unavoidable at M7**, where a 128 snapshot carries banks that are not paged in and therefore have
no address at all — and adding them now would be one semver commitment made without a caller.

The seam that could hide a bug here is a bank present in the snapshot and absent from the slot map,
which would be silently dropped. It cannot happen at M6 because the parser rejects any page the
model does not have, and that is **asserted rather than reasoned**: a test compares the parser's
bank set against the set the slot map exposes and fails if they ever diverge.

## Decision 3 — `.z80` is read and written; `.sna` is read only — **ruling**

`.sna` has no `PC` field. The program counter lives **on the guest's stack**, at the address `SP`
points to, and a `.sna` writer must therefore *push it*, destroying two bytes of the machine's RAM
to record the machine's state. A save that modifies what it is saving is not a save, and nothing
in M6's gate needs one.

Reading `.sna` is straightforward and stays, because the milestone names the format and because
plenty of software is only distributed that way. Three consequences follow from the format and are
recorded here so they are not rediscovered as bugs:

| `.sna` property | Consequence |
|---|---|
| `PC` popped from the RAM image at `SP`, then `SP += 2` | the parser reads it out of its **own** bank image, so it needs no machine |
| `SP` below `0x4000`, or `0xFFFF` (the second byte wraps into ROM) | the bytes are not in the image at all — a parse **error**, not a guess |
| only `IFF2` is stored | `iff1 = iff2` is a **convention**, wrong only for a snapshot taken inside an NMI handler, which no `.sna` writer produces |
| no T-state counter | `frame_t_state = 0`, which is the top of the frame — the interrupt window. See *What nothing covers* |

The two stale stack bytes are left in place after `PC` is popped, which is what every other
implementation does; the snapshot's RAM genuinely contained them.

**The `.z80` writer emits v3, with compressed pages.** Two reasons, and neither is file size:

- **v3 is the only version that carries the frame position.** v1 has no T-state field, and the
  additional header a v2 file declares (23 bytes, covering offsets 32–54) stops one byte short of
  it. Writing v1 or v2 would make `frame_t_state` unrecoverable through our own writer, so the
  state round trip in Decision 7 could not see it.
- **Compression gives the decompressor a symmetric partner to test against.** Without a
  compressor, `decompress` can only be graded by hand-built vectors. With one,
  `decompress(compress(page)) == page` is a property test over arbitrary pages, which is the
  strongest cheap instrument available for a codec. Its blind spot — a compressor and decompressor
  that agree on a *wrong* encoding — is the subject of Decision 7 and is closed the same way
  everything else in that decision is.

## Decision 4 — the tape is a signal, not a ROM trap — **ruling, forced by what the gate would then grade**

This is the architectural fork the milestone turns on.

**The trap.** Watch for `PC` reaching the ROM's `LD-BYTES` entry at `0x0556`, take the next block
from the tape, write it straight into the buffer `IX`/`DE` describe, set the flags the routine
would have set, and return. Perhaps fifty lines. It works today.

**The signal.** Model the `EAR` input — bit 6 of a read from port `0xFE` — as a real level that
changes on a schedule of T-states, and let the ROM's own edge-counting loop read it.

The trap is rejected, on four grounds in descending order of importance.

**1. It makes M6's gate grade the trap.** The trap bypasses the ULA, the contention model, the
frame clock, the interrupt window and the port decoding — every part of the machine M5 could not
grade. "A real game runs" would then mean "the injection works and the ROM's post-load code runs",
which says nothing about the machine. `STATUS.md` records three occasions where this project
shipped evidence that graded less than it appeared to, and calls the third *"the worst form so
far"*. Choosing the trap would be the fourth, **with the reason known in advance**, which is a
different and worse category than the first three.

**2. It does not cover the software it is for.** The trap works only for programs that call the
ROM routine. Most commercial games use their own loader, precisely to be faster and harder to
copy, and those loaders read `0xFE` directly. So the trap is not a cheaper version of the job; it
is a different job, after which the real one is still undone.

**3. The signal path is what the rest of the machine needs anyway.** `ula.rs` already names the
`EAR` bit as *"the tape port M6 brings"*, and names the issue-2/issue-3 detection that depends on
it. There is nothing to build twice.

**4. It is not expensive.** A pulse train, an advance hooked to the same place the clock advances,
and one bit in `in_port`. The `.tap` → pulse-train conversion is a fixed set of published
timings — pilot, sync, and two bit lengths. It is smaller than the contention model already
shipped.

**The risk of choosing the signal, stated plainly:** if it does not work, there is no fallback and
the milestone stalls. The mitigation is that the signal path is gradeable **below** the level of a
game, and corpus-free — see Decision 8. That mitigation is what makes this decision affordable;
without it the trap would be the pragmatic choice and the milestone's claim would have to be
weakened to match.

**A trap is not forbidden forever.** As a debugging convenience — "skip this loader, I am testing
something else" — it is legitimate. If it ever lands, two rules apply: it is **off by default**,
and the tape gates **assert that it is off**. Otherwise a gate silently starts passing through the
shortcut, which is this failure class exactly.

The related hazard is auto-start: sniffing `PC` to begin playback when the ROM starts listening.
That is a real convenience and it is a trap in disguise if it is allowed to grow. Rule: if it is
added, it may **start playback and nothing else** — never supply data — and the distinction is
stated at the site. At M6 playback is started explicitly and nothing sniffs `PC`.

## Decision 5 — the tape's internal form is a pulse train; `.tap` is a converter into it — **derived**

The obvious internal representation of a `.tap` is its own structure: a list of blocks. That is
wrong for the same reason storing a `.z80` was wrong in Decision 2, and here the consequence is
concrete rather than stylistic.

**`.tap` cannot represent a custom loader's tape at all.** It is block data with the ROM's standard
timings implied; nothing in it can say "this loader uses 700-T-state bits". `.tzx` exists for
exactly that, and it is what most commercial games are actually distributed as. A block-list
internal form would make `.tzx` a rewrite of the tape subsystem; a pulse-train internal form makes
it a second converter, with the ULA side untouched.

```rust
pub struct Tape {
    /// Lengths in T-states of successive half-periods of the EAR signal.
    pulses: Vec<u32>,
    index: usize,
    remaining: u32,
    level: bool,
    playing: bool,
}
```

Materialising every pulse costs about 16 `u32`s per data byte plus the pilot tone, so a 48 KB tape
is under a million entries — a few megabytes (**derived**, not measured; it is also irrelevant,
since `ARCHITECTURE.md` makes performance a non-goal and this is not on any hot path). A lazy
generator would save that and cost a state machine; the flat vector is simple enough to assert
exactly — a one-byte block's pulse train can be written out in a test — and that is worth more.

**The tape advances wherever the clock advances.** Contention means the clock does not advance one
T-state at a time, so the tape cannot be driven from `tick` alone. `Ula` gains one private
`fn advance(&mut self, t: u32)` that moves the clock *and* the tape, and the three existing
`self.clock.advance(..)` call sites — in `contend`, `begin_port_cycle` and `tick` — route through
it. One place, so the two clocks cannot drift.

Two deliberate non-events:

- `Ula::set_frame_t_state` (Decision 2) does **not** advance the tape. Restoring a snapshot is not
  elapsed time.
- `Ula::reset` does **not** rewind the tape. Pressing reset does not rewind a cassette.

**With no tape inserted, bit 6 reads low, exactly as it does today.** `UNDRIVEN_INPUT_BITS` is
already `0xA0` — bits 7 and 5 — so bit 6 is already clear and the constant does not change. The
assertion that M5's behaviour is untouched already exists and is external to `ula.rs`:
`tests/common/mod.rs` pins `IDLE_HALF_ROW = 0xBF` as *"the literal a real `IN A,(0xFE)` returns"*,
and `keyboard_matrix.rs` checks it across the full membrane. If inserting no tape ever changes bit
6, that gate goes red.

**The sampling point is an approximation and its size is known.** `Ula::in_port` runs after the
cycle's contention stall is charged and before its four nominal T-states arrive as ticks, so the
level is sampled up to four T-states early relative to where real hardware latches it. The ROM's
loader distinguishes a 855-T-state half-bit from a 1710-T-state one, so four T-states is far inside
its tolerance. A turbo loader with tighter margins is where it could matter, and a turbo loader
failing is what would decide it.

## Decision 6 — the parser consumes; it never indexes — **ruling, with a structural argument**

This crate builds with `panic = "abort"` in release, so a panic is not a recoverable error — it
kills the process, and `catch_unwind` is not available as a backstop. A snapshot parser reads
attacker-controlled lengths, counts and page numbers. So the requirement is not "do not panic on
the inputs we tested"; it is **remove the constructs that can panic**.

With `unsafe_code = "forbid"` there are exactly three panic sources in safe Rust that a hostile
file can reach: slice indexing, arithmetic overflow, and explicit `panic!`/`unwrap`/`expect`. Each
is closed by construction rather than by care:

| Source | How it is made unreachable |
|---|---|
| slice indexing | **there is no indexing.** One private `Reader<'a>` cursor; `u8()`, `u16_le()` and `take(n)` each return `Result`, and the single slice operation in the module is inside `Reader::take`, written once with `split_at_checked`. Nothing else in `snapshot/` touches a `[..]` |
| arithmetic overflow | every quantity derived from the file is widened (`usize::from(u16)`, `usize::from(u8)`) or combined with `checked_add`. **`overflow-checks = true` in every profile makes an overflow an abort, not a wrap** — and this project has already shipped exactly that defect once, the `u8` T-state accumulator a 63-byte prefix run overflowed |
| unbounded allocation | **no allocation is ever sized from the file.** Decompression fills a fixed `[u8; PAGE_SIZE]` through a write cursor; a write past the end is `PageOverrun`, not a `Vec` growing to whatever the file asked for |
| non-termination | every loop iteration consumes at least one input byte, so progress is structural. A run-length count of zero emits nothing and still consumes its four bytes |
| `unwrap` / `expect` | none in `snapshot/` or `tape/`. This is the one item on the list that a grep enforces rather than a type, and it belongs in the milestone's review checklist |

**How this is proven rather than asserted**, since the project's own doctrine is that prose
claiming a protection is a hypothesis and not a guarantee:

- **An exhaustive truncation sweep.** For a valid file of length *N*, `parse(&file[..k])` for
  **every** `k` in `0..N` must return `Err`, never panic, never `Ok`. This is cheap only if *N* is
  small, so the fixture is built to be small: a snapshot whose banks are uniform compresses to a
  few dozen bytes per page, giving a whole file of a few hundred bytes. Exhaustive over the axis
  that matters, deterministic, and it runs on every `cargo test`.
- **A `proptest` over arbitrary `Vec<u8>`** and over byte-level mutations of a valid file,
  asserting only that `parse` returns. `proptest` is already a dev-dependency of `spectrum`.
- **`cargo fuzz` is the right long-run instrument and is not the gate**, because it needs nightly
  and a corpus that grows outside the repository. The two above are the committed substitute, and
  saying which is which matters more than having both.

### The `.z80` compression scheme, and every hostile case in it

The scheme is one escape: `ED ED <count> <byte>` means `<byte>` repeated `<count>` times. A lone
`ED` is literal. v1 encodes the whole 48 KB image as one block terminated by `00 ED ED 00`; v2 and
v3 encode each 16 KB page separately, with a two-byte length prefix, and the length `0xFFFF` means
"16384 bytes, uncompressed" rather than a length.

| Input | Verdict |
|---|---|
| `count` large enough to overrun the page | `PageOverrun`. The destination is fixed-size, so this is a cursor bound and not a length check |
| `count == 0` | legal; emits nothing, consumes four bytes, loop still progresses |
| `ED ED` with fewer than two bytes after it | `Truncated` |
| v1 block with no `00 ED ED 00` terminator | `Truncated` |
| decompressed output shorter than the page | `PageUnderrun` — **strict**, deliberately. Zero-filling would produce a wrong machine that every round trip then agrees is right. What would change this ruling: an observed real-world file that is legitimately short |
| declared page length longer than the remaining input | `Truncated` |
| page length `0xFFFF` | 16384 raw bytes. Must not be read as a 65535-byte length |
| duplicate page number | `DuplicatePage` — the alternative is a silent last-write-wins |
| page number the model does not have | `UnknownPage`. This is the parse-don't-validate boundary: a `Snapshot` that reaches `restore` cannot name a bank the machine lacks |
| hardware mode byte that is not a 48K | `UnsupportedHardware { mode }` |
| v1, uncompressed, with trailing bytes after the 49152 | error — **strict**, same ruling and same escape hatch as the underrun |

### The error type

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, thiserror::Error)]
#[non_exhaustive]
pub enum Error { /* Truncated, UnsupportedVersion, UnsupportedHardware, ... */ }
```

`Copy`, allocation-free, `#[non_exhaustive]` — matching `StepError`, `RomSizeError` and
`InvalidInterruptMode`, the three error types this workspace already has. `thiserror` is already a
dependency of `spectrum`. Every variant names the byte or offset that failed, because a parse
error a user cannot act on is a stack trace with better formatting.

Two error types, not one: `snapshot::Error` and `tape::Error`. A malformed tape is not a malformed
snapshot, and the siblings here are all small and specific rather than one crate-wide enum.

## Decision 7 — the round trip is three round trips, and each one alone is a lie — **derived; this corrects `MACHINE.md`**

`MACHINE.md` ranks this third in its verification plan:

> **A snapshot round trip.** Load a `.z80`, run zero frames, save, compare. Byte-identical or the
> state model is wrong. Cheap, deterministic, and independent of timing.

It is the strongest instrument M6 has and the ranking is right. **The sentence, as written, is not
achievable, and believing it is would corrupt the design.** Two reasons:

- **A foreign file carries bits the machine does not model.** `.z80` v1's byte 12 packs the border
  into bits 1–3 and the high bit of `R` into bit 0 — and also a flag for hardware this machine does
  not have, and bits with no defined meaning. Our writer emits zero there. Byte-identity over a
  foreign file would therefore force `Snapshot` to carry bits that are not machine state, which is
  precisely what Decision 2 exists to prevent. (`R` split across two bytes is worth noticing for a
  second reason: it is the archetype of a field a symmetric bug hides, since a parser that forgets
  bit 12.0 and a writer that never sets it round-trip perfectly and lose the top bit of `R`.)
- **A foreign file is in a foreign encoding.** A v1 compressed file re-serialised as v3 compressed
  is a different byte string for the same machine, and that is correct behaviour.

So byte-identity holds only over files in our own canonical encoding — which makes it a check of
the codec against *itself*. Decomposed honestly, there are three round trips and they grade three
different things:

| | Round trip | Grades | Blind to |
|---|---|---|---|
| **R1** | `snapshot(restore(s)) == s` for a `Snapshot` built in code | the applier: every field reaching the machine and coming back | fields no format carries; a field the machine drops symmetrically |
| **R2** | `parse(write(s)) == s` over arbitrary `Snapshot`s | the codec: header offsets, page framing, compression | a header offset that `parse` and `write` get **equally** wrong |
| **R3** | `write(parse(f)) == f` for `f` in canonical form | that R1 and R2 compose | everything R2 is blind to, plus foreign encodings |

**R1 is the strongest and the cheapest, and it needs no format at all.** It is `Snapshot` →
`restore` → `snapshot()` → compare. It runs on a bare clone with no corpus and no file, and it is
the test that catches `restore` forgetting a field.

### What no round trip can see, and what does see it

Every one of the three compares a value against a value that came from the same code. A symmetric
error survives all three:

- a field **permuted** with another of the same width — `parse` swaps `de` and `hl`, `write` swaps
  them back
- a field read from the **wrong offset** by both sides
- a field **dropped in both directions** — `parse` leaves it at its default and `write` always
  emits that default. **The round trip is then green because both sides agreed to lose it.**

That last one is not hypothetical here. It is the M4 defect, verbatim, in a different file:
`STATUS.md` records the FUSE harness defaulting `q` to zero, and the finding that *"zero is the one
value that makes a positive false claim"*. A snapshot loader is the same shape — a state-restoring
harness with a field nothing else looks at.

Only two things break the symmetry, and both are required:

**1. One hand-transcribed vector per format and version.** A small file written out as a
`const [u8; N]` in the source, **byte by byte, each with a comment naming its offset and its
meaning from the format description**, and its expected `Snapshot` written out separately, field by
field. Neither is derived from the other. This is the `MEMBRANE` pattern from
`tests/common/mod.rs`, and that table's own documentation records what it was worth: under a review
that permuted the keyboard map, *"38 of the 40 keys moved and the suite stayed at 72 passed with a
green boot gate"*. A derived expectation gets the wrong answer right in both places at once.

**2. The fixture's fields must be pairwise distinct and none of them zero** — otherwise a
permutation is invisible even to a hand-written expectation, and a dropped field looks like a
correct default. **The test asserts this about its own fixture**, so the fixture cannot quietly
decay into one that cannot separate anything.

### The one field with the highest risk, named

The `.z80` v3 T-state counter is **not** a plain frame position. It is reported to be split across
a low word and a high byte, where the high byte selects which third of the frame and the low word
counts *down* within it. That means the conversion is a small non-linear function with an inverse,
and it is the single field where a confident-sounding formula is most dangerous.

- It must be **one function with its inverse beside it**, and graded exhaustively over all 69888
  frame positions. That is cheap and genuinely exhaustive: one input, one output, no other axis —
  which is worth saying explicitly, because `STATUS.md` records the opposite case, where an
  exhaustive sweep on one axis was *narrower* than the sample it replaced on another.
- **The exhaustive test cannot tell you the formula is right.** It grades the pair against each
  other. If both halves encode the same wrong scheme it is green and every `.z80` we write is
  unreadable elsewhere.
- What settles it: the hand-transcribed vector's own T-state field, and the external oracle below.

**Do not take the shape above as verified.** It is the strongest single hazard in this design and
the implementer must read it out of the format description rather than out of this paragraph.

### The external oracle, which M6 has and M5 did not

Loading one of our own `.z80` files in a third-party emulator, and one of theirs here, are two
checks against an **independent implementation**. They are manual and they are observation — a
human looks at a screen — but they are observation of a different codebase's reading of the same
document, which is a materially different thing from observing our own. It is the only instrument
that grades a symmetric misreading of the format, and it costs one file and five minutes.

It belongs in the record, with the emulator named and the date, for the same reason every
re-measured row in `ARCHITECTURE.md` now ships with the command that produced it.

## Decision 8 — the gate is corpus-free by construction, and a corpus can only strengthen it — **ruling**

`MACHINE.md` ranks *known-demanding software* fifth and labels it observation. `STATUS.md` records
three gates that ran nowhere, the last of which — the M5 boot gate as an `examples/` binary — it
calls the worst form so far. M6's stated gate depends on files that **may not be redistributed**,
so by default its corpus is absent, and a gate whose corpus is absent by default is a gate that
runs nowhere. Proposing that and hoping would be the fourth instance.

The way out is not a better opt-out policy — `crates/testsupport` already implements the right one,
and M6 uses it unchanged rather than inventing a second convention. The way out is to **design the
gate so its data is data we authored**, and then to be exact about the residue that genuinely
cannot be.

### Four tiers

| Tier | What it is | Evidence class | Corpus | Runs |
|---|---|---|---|---|
| **T1** | R1/R2/R3, the truncation sweep, the codec property tests, the hand-transcribed vectors | **proven** — deterministic, self-contained | none: the fixtures are built in code and the vectors are bytes we wrote | every clone, every CI run |
| **T2** | The real ROM's `LD-BYTES` loads a synthetic tape through the `EAR` bit | **measured** — binary pass/fail against a program we did not write | `testdata/roms/48.rom`, already committed | wherever the M5 boot gate runs |
| **T3** | A program **we wrote** is loaded from tape by the ROM and then executes and writes a signature into RAM | **measured** | the same committed ROM | same |
| **T4** | A real game loads and reaches its title screen; one of our `.z80` files opens in a third-party emulator | **observed** | user-supplied, absent by default | manually, recorded in `STATUS.md` |

**T2 is the load-bearing one and it is worth being precise about.** The real ROM's loader is
entered at `0x0556` with `IX` as the destination, `DE` as the length, `A'` as the expected flag
byte and carry set for load-rather-than-verify; it does its own `DI`. Give it a tape we generated
from bytes we chose, run the machine until it returns to a sentinel return address or a step budget
expires, and assert the bytes landed and that carry came back set. That exercises the pulse
timings, the `EAR` bit position, the ULA port decoding, the clock's absolute progression, and the
memory map — **through the real machine, against a loader we did not write, with only a committed
corpus.**

What it does *not* grade, which must be said in the same breath: the ROM's edge detection has wide
tolerances, so **timings that are some way off still load**. T2 grades the mechanism, not the
precision. Nothing in M6 grades the precision, and `MACHINE.md`'s verification item 2 — a
known-timing test program — remains the only thing that would.

**T3 is what replaces "a real game runs" as the *gate*.** A few dozen bytes of Z80, assembled as a
byte array in the test, loaded from tape by the ROM, executed, and observed to have run. It is
genuinely "a program loads from tape and runs", it is deterministic, and it commits, because we
wrote it. What it does not cover, and what only T4 covers, is a **custom turbo loader** and the
sheer breadth of behaviour a commercial game exercises.

### So what is M6's gate, in the project's own vocabulary

**M6's gate is T1 + T2 + T3. `MACHINE.md`'s "a real game runs" is T4, and T4 is observation that
cannot be automated in a repository that may not carry games.** That is a correction to the
milestone table, made in the open rather than by quietly narrowing what the row meant.

The residue is real and is not apologised for: T4 is the only tier that grades a turbo loader, and
it is the only tier that will run a program written by someone who did not know how our emulator
works. Nothing shrinks that to zero. What M6 does is shrink it from *the whole gate* to *the part
that genuinely cannot be committed*.

### The corpus tier, when it exists

If a user has files, they should be swept, and the sweep uses the existing policy verbatim:

- `testdata/snapshots/*.z80`, `*.sna` and `testdata/games/*.tap` are **directory sweeps**, not named
  files. Every file present must parse; every `.z80` must survive R3.
- Absent → `testsupport::skip_absent_corpus` decides: **fail** when undeclared, skip under
  `ZX_CORPUS_ALLOW_MISSING`, **refused** under `CI`. One convention, not one per corpus, which is
  the thing `testdata/README.md` already promises.
- **It is a `#[test]`.** Not an example, not a binary, not a `main` that prints a verdict. That
  sentence exists because it is the M5 finding and it is the cheapest possible way not to repeat
  it.

### One thing worth noticing about what M6 unlocks

`MACHINE.md`'s verification item 2 — the community timing-test programs that report measured
T-state counts — is *"the closest thing to an oracle available, and it is a real one"*, and it is
the settling condition for the open `FIRST_CONTENDED_T_STATE` question. Those programs are
distributed as tapes and snapshots. **M6 is the milestone that makes running them possible at all.**
Whether any of them may be committed to `testdata/` is a licensing question this document does not
answer; if one may, it becomes the first genuine machine-level oracle this project has, and it
belongs under the same policy as everything else there.

## Decision 9 — no `.szx` — **ruling (YAGNI)**

`.szx` is a better format than `.z80`: chunked, extensible, and it carries CPU state the others do
not — including `MEMPTR`, which is the one field Decision 7 identifies as unpreservable.

It is still out of scope, for three reasons:

1. Its extensibility pays off at **M7**, where the AY registers, the paging port and the second ROM
   all need somewhere to live and `.z80` v3 carries them awkwardly. Adding it now is building for a
   milestone whose requirements are not yet fixed.
2. Its `MEMPTR` advantage buys nothing **measurable** today: nothing in this project can grade
   `wz`, so preserving it would be an unverifiable improvement to an unverifiable field.
3. A third parser triples the hostile-input surface of Decision 6 for no additional gate.

M6 already cut scope once, in Decision 3, by making `.sna` read-only. Adding a third format while
the second is deliberately half-implemented would be incoherent.

## Public API delta

Every item below is a semver event and needs approval. `Ula`, `Memory`, `Clock` and `CpuState`
grow **no public items at all** — the four helpers the applier needs are `pub(crate)`, which is
Decision 1's payoff and the only hard evidence in it.

| New public item | Why it is unavoidable |
|---|---|
| `pub mod snapshot` | the milestone's subject |
| `snapshot::Snapshot` (`pub cpu`, `pub border`, `pub frame_t_state`; banks private) | nothing existing represents a machine's state as a value |
| `Snapshot::bank(BankIndex) -> Option<&[u8; PAGE_SIZE]>` | a failing comparison must be able to say *where*; a debugger reads RAM out of a snapshot |
| `snapshot::Error` (`#[non_exhaustive]`) | a parser of untrusted input returns typed failures |
| `snapshot::z80::parse` / `::write` | read and write the canonical format |
| `snapshot::sna::parse` | the milestone names the format. **No `sna::write`** — Decision 3 |
| `Spectrum::snapshot()` / `Spectrum::restore()` | the applier; the shell half of Decision 1 |
| `pub mod tape` | the milestone's second subject |
| `tape::Tape` + `play` / `stop` / `rewind` | the minimum any consumer needs to load anything |
| `tape::Error` (`#[non_exhaustive]`) | as above, for a different subject |
| `tape::tap::parse` | the milestone names the format |
| `Spectrum::insert_tape()` / `Spectrum::tape_mut()` | the tape lives on the `Ula`, which the machine owns |

**New `pub(crate)` items** — public surface unchanged: `Ula::set_border`, `Ula::set_frame_t_state`,
`Ula::insert_tape`, `Ula::tape_mut`, `Ula::advance`, `Snapshot::set_bank`.

**Deliberately absent, and non-breaking to add later:** `sna::write`, `Tape::is_finished`,
`Tape::position`, `Spectrum::eject_tape`, `Memory::bank` / `bank_mut` (M7),
`snapshot::szx` (Decision 9). Each is one item this milestone does not need a caller for.

`CHANGELOG.md` currently describes itself as *"changes to the published surface of `crates/z80`"*.
M6 is the first milestone to move `spectrum`'s surface, so that scope sentence widens rather than a
second changelog appearing — one file, one owner, the same rule `ARCHITECTURE.md` applies to the
open register.

## What M6 deliberately does not do, and who needs it

| Not done | Who needs it |
|---|---|
| **`.tzx`** — the only format that can carry a custom loader's timings | anything past T3 on real software. The pulse-train decision makes it a converter rather than a rewrite; it is the first thing to add if T4 fails |
| **Tape saving** (`MIC` out → `.tap`) | nothing yet. Needs the `0xFE` write bits M6 still discards |
| **Sound** — the speaker bit of a `0xFE` write | M8 |
| **Floating bus** | unchanged from M5, and unchanged for the same stated reason: there is no oracle for the byte-to-phase mapping, and a plausible guess is wrong invisibly where a constant is wrong visibly. Some games read it |
| **Issue 2 / issue 3 `EAR` readback** — writing bit 3 or 4 and reading bit 6 back | a real cause of "loads on one emulator, not another". Named here so it is the first thing suspected if a specific loader fails |
| **128 hardware modes in `.z80`** | M7. Today they are `UnsupportedHardware`; at M7 those rejections become support, and that is where a `Model` enum earns its second variant. A one-variant enum today would be scaffolding |
| **AY register state, the paging port, the second ROM** | M7, and the reason to prefer `.szx` there |
| **`Memory::bank` / `bank_mut`** | M7, where a snapshot carries banks that are not paged in and therefore have no address |

## What nothing covers

`MACHINE.md` asks for this list explicitly, and `STATUS.md` records that *"reporting the absence of
a distinguishing test as evidence of correctness is the failure this project keeps catching"*.

| Property | Covered by |
|---|---|
| `.z80` v1 header field offsets | the hand-transcribed vector — **not** by any round trip |
| `.z80` v2/v3 additional-header offsets | one hand-transcribed vector **per version**, or **nothing** for the version that lacks one |
| `.sna` header field offsets | the hand-transcribed vector only. There is no writer, so `.sna` has **no round trip at all** |
| The compression codec | R2 plus the hand-built compressed vector |
| The frame-position ↔ T-state-counter conversion | exhaustive self-round-trip, which **cannot see a wrong formula**, plus one transcribed value |
| `restore` applying every field | R1 — **only** because the fixture varies every field distinctly, which the test asserts about itself |
| `CpuState::wz` | **nothing.** No format carries it; the parser sets zero. Observable only through the undocumented flag bits of a `BIT n,(IX+d)` executed before anything else sets it, and `crates/z80` does not yet update `wz` from un-prefixed instructions at all. Small, real, and unfixable by any format `MACHINE.md` names |
| `CpuState::q` | derived at parse from `F`, which is the ruling `STATUS.md` already made — *"loading a state is a `POP AF`; the load is the last thing that wrote `F`, so the latch must equal it"*. It has **no oracle**, exactly as it had none at M4 |
| The FLASH phase across a load | **nothing.** No format carries it and our model derives it from `frames()`, which `restore` leaves alone. A snapshot taken mid-flash renders inverted for up to 16 frames after loading |
| `.sna`'s missing frame position | **nothing.** It restores at `frame_t_state = 0`, which is inside the interrupt window — so a `.sna` load takes an interrupt almost immediately. That is what other implementations do and it is what most `.sna` files expect, but it is a convention, not a measurement |
| Pulse timings against **hardware** | **nothing.** T2 shows the ROM accepts them; the ROM's tolerance is wide |
| The `EAR` sampling point within an `IN` cycle | **nothing.** Approximated to the start of the cycle, ≤4 T-states early |
| Contention during a tape load | **nothing.** It is exercised (the loader writes into contended RAM) and not graded — the loader does not depend on it |
| Turbo loaders | **nothing.** `.tap` cannot represent them |
| Our reading of either format | **only** the third-party-emulator check, which is manual observation |
| A real game | T4: observation, corpus-dependent, absent by default |

## Implementation order

Each step is independently reviewable and each has a gate that goes red without the next one.

1. **`Snapshot`, `Spectrum::snapshot()`, `Spectrum::restore()`, and the four `pub(crate)` setters.**
   No parsers. Gate: **R1** over a `Snapshot` built in code, plus the assertion that the fixture's
   fields are pairwise distinct and non-zero, plus the assertion that the bank set the parser will
   produce equals the set the slot map exposes. This is the milestone's spine and it needs no file
   format to exist.
2. **`Reader`**, with its own unit tests for every truncation case. Nothing else in `snapshot/`
   slices.
3. **`.z80` v1 read.** Gate: hand-transcribed vector, exhaustive truncation sweep, the hostile-input
   table of Decision 6 as one test per row.
4. **The compression codec, both directions.** Gate: `decompress(compress(page)) == page` as a
   property test, with named adversarial pages — all-`ED`, runs of exactly four and five, an `ED`
   at the page boundary — and the hand-built compressed vector as the asymmetric anchor.
5. **`.z80` v2/v3 read, and the v3 writer.** Gate: R2, R3, the transcribed vector per version, and
   the exhaustive frame-position conversion test.
6. **`.sna` read.** Gate: transcribed vector; the `SP`-outside-RAM cases; and cross-format
   agreement — parse a `.sna`, write it as `.z80`, read it back, compare `Snapshot`s.
7. **`Tape`, the pulse train, `.tap`, `Ula::advance`, the `EAR` bit.** Gate: the exact pulse train
   of a one-byte block asserted by hand; a decoder written in the test that reads our own pulse
   train back into bytes; and `IDLE_HALF_ROW` still `0xBF` with no tape.
8. **T2 — the ROM's `LD-BYTES` against a synthetic tape.**
9. **T3 — a program we wrote, loaded from tape and executed.**
10. **The corpus sweeps** (`testdata/snapshots/`, `testdata/games/`), through
    `testsupport::skip_absent_corpus` unchanged.
11. **Documentation**, as a step and not a tidy-up: the register rows below into `STATUS.md`, the
    `spectrum` surface into `CHANGELOG.md`, the milestone row in `README.md`, the two new corpus
    directories into `testdata/README.md`, and the doc-comment sweep `STATUS.md` requires at every
    milestone boundary — which for M6 specifically means `ula.rs`'s *"`EAR` input — **no**"* row
    and its *"the tape port M6 brings"* sentence, both of which M6 falsifies.

## What this document could not settle

- **The exact `.z80` v3 T-state encoding.** Its shape is described in Decision 7 and flagged as the
  highest-risk field in the design. Nothing in this repository can adjudicate it, and neither can
  the exhaustive test that will be written for it. Reading the format description, and then loading
  one of our files elsewhere, is what settles it.
- **Whether a third-party-produced `.z80` or `.sna` may be committed.** It is the only instrument
  that separates *the format* from *our reading of the format*, and it is one small file. This is a
  licensing and policy call for the user, not a design decision.
- **Whether `.tap` is sufficient for T4 at all.** If the games available are turbo-loader titles —
  and most commercial ones are — then no `.tap` can carry them and T4 cannot pass at M6 regardless
  of how correct the machine is. This bears directly on whether the milestone can be declared done,
  and it is answered by looking at the actual files, not by more design. If the answer is no,
  `.tzx` moves from *later* to *required*, and Decision 5 is what makes that cheap.
- **Whether `restore` should reset `frames()`.** It is left alone, for a stated reason (uptime
  means one thing), but the alternative is defensible and the FLASH-phase discontinuity is the
  visible cost. A user noticing the flash jump after a load is what would decide it.
- **The `EAR` sampling point within an `IN` cycle.** Approximated to the start; the error is at
  most four T-states and is far inside the ROM's tolerance. A specific turbo loader failing is what
  would decide it, and there is nothing to be gained from guessing sooner.
